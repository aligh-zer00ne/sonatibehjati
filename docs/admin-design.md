# بازبینی ظاهر و کارکرد پنل

مرجع بصری این بازطراحی، فایل HTML سامانهٔ سهامداران و تصاویر ارسالی کارفرماست. ساختار حسابداری، داده‌های نمونه، کاربران و نشان آن سامانه وارد پروژه نشده‌اند. رنگ‌های زرشکی گرم، طلایی و کرم، نشان واقعی سنتی بهجتی و فونت فعلی پروژه حفظ شده‌اند.

## رفتار مشترک

کارت‌های بخش‌ها، دریافت و پرداخت، سفارش‌ها، مشتریان، محصولات و آمار از یک الگوی بازخورد استفاده می‌کنند: حاشیهٔ زرشکی، سایهٔ نرم، هالهٔ ثابت گوشهٔ کارت و چرخش ظریف آیکون. حرکت سه‌بعدی کارت با موس حذف شده است. کارت با هاور کمی بالا می‌آید و دکمه هنگام فشردن بازخورد کوتاه دارد. لمس، پیمایش و مسیر اصلی دکمه‌ها حفظ شده‌اند؛ کارت اطلاعاتی به دکمهٔ ساختگی تبدیل نشده است.

فوکوس صفحه‌کلید مشخص است. با تنظیم Reduce motion در سیستم، چرخش/حرکت و شبکهٔ متحرک متوقف می‌شوند. پس‌زمینه‌های زرشکی جابه‌جا نمی‌شوند و شبکهٔ نقطه‌ای آن‌ها هنگام مخفی‌شدن یا خروج از دید متوقف می‌شود. منوی بالا، منوی موبایل، کنترل‌های فرم و کارت‌های مالی رفتار هماهنگ دارند.

## بخش‌های اصلی

- **داشبورد:** حلقهٔ وضعیت سفارش در یک قاب زرشکی، تعداد و سهم هر وضعیت با هاور/فوکوس، رنگ‌های خوانا و نمایش سفارش‌های همان وضعیت با کلیک یا صفحه‌کلید. شمارنده‌ها و آمار از پاسخ واقعی API هستند؛ فیلتر محل خرید، بازه‌ها و تازه‌سازی حفظ شده‌اند.
- **محصول:** فرم بخش‌بندی‌شده با مشخصات و قیمت، تصویر، تخفیف و وزن ارسال؛ توضیحات اختیاری ابتدا جمع هستند و مقدارشان حفظ می‌شود. افزودن و ویرایش در پنجره‌ای روی فهرست انجام می‌شود و نوار ذخیره در دسترس است. پیش‌نویس، کنترل هم‌زمانی، آپلود، اعتبارسنجی، قیمت ریالی و محافظت از فاکتورهای قبلی برقرارند.
- **کاربران پنل:** فرم ساخت همکار کنار فهرست حساب‌ها و گزینه‌های دسترسی به شکل خانه‌های مشخص؛ چیدمان در موبایل زیر هم قرار می‌گیرد. اختیار انتخاب بخش‌ها و وضعیت حساب همچنان با مدیر است؛ هیچ سطح دسترسی جدید یا خودکاری اضافه نشده است.
- **مشتری و سفارش:** فرم مشتری با اطلاعات تماس و نشانی اینستاگرام منظم‌تر شده؛ کارت‌ها و دکمه‌ها بازخورد یکسان دارند. عملیات دریافت، دفتر حساب، ارسال و پرداخت بانکی تغییر نکرده‌اند.
- **پایین پنل و ورود:** عبارت «طراحی توسط nexoraict.ir» با لینک واقعی، وزن بیشتر و قاب هماهنگ مشخص‌تر شده است.
- **چاپ:** هر سه فاکتور با متن و قاب سیاه‌وسفید آماده‌اند؛ جزئیات و تنظیم چاپ در [راهنمای چاپ](printing.md) است.
- **نقشه:** فقط نمای سبک استان‌ها وجود دارد؛ SDK و کلید نشان حذف شده‌اند. [راهنمای نقشه](order-map.md).

## بررسی و انتشار

برای بررسی محلی با API/پنل ساخته‌شده و دیتابیس مهاجرت‌شده:

```bash
npm run verify:panel-review
npm run verify:dashboard-workspace
npm run verify:admin-surfaces
npm run verify:admin-login-ui
npm run verify:retail-ui
npm run verify:invoice-workspace
```

بررسی پنل ۲۹ مسیر را در عرض‌های ۳۲۰، ۳۹۰، ۷۶۸ و ۱۴۴۰ کنترل می‌کند و ساخت/ویرایش واقعی محصول، آپلود، حفظ فیلدهای پنهان و فاکتور قبلی، ایجاد همکار و تغییر دسترسی و لمس واقعی کارت روی موبایل را بررسی می‌کند. بررسی‌های دیگر کلیک نمودار، فیلتر/صفحه‌بندی، ورود و نقش محدود، رفتار موس/لمس/کاهش حرکت، سفارش دستی/دریافت و PDF/فایل مستقل را پوشش می‌دهند. داده‌های موقت پاک می‌شوند؛ پیامک، بانک و Production واقعی مصرف نمی‌شوند. این بررسی‌ها جای آزمایش چاپگر فیزیکی فروشگاه را نمی‌گیرند.

این بازطراحی مهاجرت، کلید یا تنظیم Nginx تازه ندارد. با همان روش معمول روی سرور منتشر کنید:

```bash
git pull --ff-only origin dev && bash deploy/update-production.sh
```

فایل خصوصی محیط، تصاویر فروشگاه و داده‌های موجود را تغییر ندهید و برای این به‌روزرسانی seed/reset اجرا نکنید.

## اصلاح خوانایی و فشردگی کارت‌ها

طبق آخرین اصلاح کارفرما، عنوان‌ها و مبلغ اصلی درشت‌تر از توضیحات هستند؛ توضیحات و برچسب‌های کوچک پنل نیز خواناتر شده‌اند. اندازهٔ آیکون‌های آمار و سفارش با قاب‌های ۴۸ پیکسلی هماهنگ است. کارت‌های مشترک محصولات، مشتریان و اطلاعات براساس عرض خود بخش یک، دو یا سه ستون می‌شوند؛ بنابراین بخش باریک کاربران پنل به سه ستون نامناسب فشرده نمی‌شود. فاصلهٔ خانه‌های اطلاعات کمتر شده و آخرین فیلد تک‌افتاده به یک ردیف کوتاه تبدیل شده است. عملیات محصول با چهار آیکون دارای عنوان و نام دسترس‌پذیر نمایش داده می‌شود؛ تأیید حذف و همهٔ عملیات برقرارند.

کادر راهنمای شناور حلقهٔ سفارش‌ها حذف شده تا روی نوشتهٔ وسط نیفتد. تعداد، عنوان وضعیت و درصد همچنان در مرکز حلقه و راهنمای پایین خوانده می‌شوند؛ هاور/فوکوس و بازکردن سفارش‌های واقعی برقرار است. کارت آمار از ترکیب افقی آیکون و متن استفاده می‌کند و بخش‌های فهرست/مالی حداقل ارتفاع و فاصلهٔ کمتری دارند. فونت فاکتور و لیبل چاپی از این تغییرات عمومی پنل جدا باقی می‌ماند.

افزودن و ویرایش محصول از خود فهرست در پنجرهٔ زرشکی با بدنهٔ قابل پیمایش و نوار ذخیره باز می‌شود. لینک مستقیم مسیرهای قدیمی نیز همین پنجره را روی فهرست باز می‌کند. فرم دسکتاپ سه ستون دارد و روی موبایل تک‌ستونه است. ذخیره، فیلتر و صفحهٔ فهرست را حفظ می‌کند؛ بعد از بستن، فوکوس و محل پیمایش برمی‌گردند. بستن با ضربدر، Escape، پس‌زمینه یا انصراف از همان محافظ پیش‌نویس و آپلود/ذخیره عبور می‌کند. خطای ذخیره و تعارض نسخه پنجره را نمی‌بندد. همهٔ چهار بخش فرم، پیش‌نویس، آپلود، مقادیر پنهان و ریال نمایش‌داده‌شده حفظ می‌شوند.

## اعلامیهٔ قیمت

ویرایش گروهی قیمت‌ها با سربرگ زرشکی، شمارش کالا/تغییر، جستجوی خوانا و دسته‌های قابل پیمایش انجام می‌شود. ردیف تغییرکرده با حاشیهٔ طلایی و اختلاف قیمت مشخص است و بازگرداندن هر قیمت در همان ردیف در دسترس است. جستجو تفاوت ی/ک عربی و فارسی و بزرگی حروف را یکسان می‌کند. تغییر دسته یا جستجو پیش‌نویس قیمت‌ها را حذف نمی‌کند؛ ذخیره همهٔ تغییرها، شامل موارد پنهان را ثبت می‌کند.

در موبایل عنوان و آمار کوتاه‌ترند، دسته‌ها افقی پیمایش می‌شوند و نوار ذخیره جای کمتری می‌گیرد تا خود کالاها زودتر دیده شوند. قیمت‌ها همچنان ریال نمایش داده می‌شوند؛ کنترل نسخه، ذخیرهٔ یکپارچه، تلاش دوباره پس از قطع پاسخ، اعتبارسنجی و حفظ فاکتورهای قبلی همان رفتار قبلی را دارند.

## پنجرهٔ جزئیات و تاری پس‌زمینه

جزئیات سفارش‌های وبسایت و دستی از فهرست، داشبورد، حساب مشتری و نقشه، روی همان صفحه در پنجره باز می‌شود. مسیر مستقیم سفارش هم همین پنجره را روی فهرست می‌آورد. تغییر وضعیت سفارش بالای جزئیات، تب‌های اطلاعات و دکمه‌های چاپ در دسترس‌اند؛ سفارش دستی همچنان فقط محصولات و چاپ دارد. انتخاب وضعیت ثبت‌نشده هنگام بستن تأیید می‌گیرد و حین ثبت، پیگیری بانک یا چاپ، بستن پنجرهٔ والد محافظت می‌شود. به‌روزرسانی فهرست پنجره را از بین نمی‌برد و فیلترها حفظ می‌شوند.

حساب و فاکتورهای مشتری از کارت مشتری و جزئیات تراکنش‌های لینک پرداخت نیز در پنجره باز می‌شوند. بخش‌های اصلی و فرم‌های مستقل دریافت و پرداخت مسیرهای اصلی خود را دارند. پنجره‌های موجود، از جمله ویرایش محصول، مشتری، تخفیف و کاربران نیز پس‌زمینهٔ تار یکسان دارند. بدنهٔ پنجره در موبایل پیمایش می‌شود؛ Escape، ضربدر، فوکوس و بازگشت به دکمهٔ قبلی بررسی می‌شوند. چاپ تمام‌صفحه روی پنجرهٔ سفارش باز می‌شود و با بستن چاپ، به همان جزئیات برمی‌گردید؛ فرم قدیمی شخصی‌سازی لیبل برنمی‌گردد.

## Customer message templates and shipping

Management → قالب پیام‌ها (`/admin/message-templates`) owns reusable payment and shipment text. Grant MESSAGES to staff who may edit templates; ORDERS alone can use them. Insert supported Persian placeholders using the buttons; payment text must retain `{لینک_پرداخت}` and shipping text `{کد_رهگیری}`. Choose a saved template in the payment-link/order composer, review its real values, then copy the whole text, share it or open SMS on the phone. The site never treats opening a composer as confirmed sending. No SMS provider configuration is required for this feature.

Website and Instagram details keep carrier/tracking beside the main actions. Saving a tracking code atomically records SHIPPED plus an audit entry, subject to current order/label versions and the existing website bank-confirmation rule. Printing and notifications use those same saved values. In-person orders have no shipment notification action. Historical shipping charges and payments are unchanged.

Deployment needs additive migration `202610230005_message_templates`, handled by `deploy/update-production.sh`. Verification: `npm run verify:customer-messages`, `npm run verify:payment-links-ui`, `npm run verify:admin-orders-ui` and `npm run verify:retail-ui`. Tests use temporary records and mock native sharing/bank/SMS; no external message is sent.
