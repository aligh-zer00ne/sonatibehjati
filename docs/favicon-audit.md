# بررسی favicon سنتی بهجتی — ۲۱ اکتبر ۲۰۲۶

## نتیجه

در زمان این بررسی، مشکل فنی قابل بازتولیدی در تحویل favicon روی دامنهٔ اصلی پیدا نشد. سایت واقعی هم‌اکنون آیکون صحیح برند را در HTML اولیه معرفی می‌کند و فایل آن قابل دریافت است. نبودن آیکون در نتایج گوگل، به‌تنهایی ثابت نمی‌کند که تنظیم سایت خراب است. دلیل قطعیِ انتخاب گوگل از بیرون سایت قابل تشخیص نیست؛ بازخزش/پردازش گوگل یکی از احتمال‌هاست، نه نتیجهٔ اثبات‌شده.

هیچ تصویر، طراحی صفحه، قابلیت فروشگاه، نام برند، robots یا تنظیم نامرتبط SEO تغییر نکرد. PNG موجود شرایط درخواستی را دارد و دوباره تولید نشده است. تنها تغییر اجرایی این بررسی، تقویت آزمون favicon موجود برای تشخیص اعلان تکراری و اطمینان از دریافت بایت‌های واقعی تصویر در خروجی Production است.

## شواهد دامنهٔ اصلی

این جدول حاصل درخواست‌های واقعی HTTPS به `https://sonatibehjati.ir` است، نه تست localhost. TLS بررسی شد؛ از `curl -k` استفاده نشد. برای مرورگر عادی، Googlebot و Googlebot-Image درخواست‌های جدا ارسال شد.

| مورد                               | نتیجهٔ مشاهده‌شده                                                                                                                  |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| صفحهٔ اصلی                         | HTTP 200، `Content-Type: text/html; charset=utf-8`                                                                                 |
| HTML بدون اجرای JavaScript         | دقیقاً یک `rel="icon"` با `href="/icon.png"`، `type="image/png"` و `sizes="192x192"` در head                                       |
| PNG اصلی                           | `https://sonatibehjati.ir/icon.png`، HTTP 200 بدون redirect، `Content-Type: image/png`                                             |
| فرمت و اندازهٔ واقعی               | امضای PNG معتبر، عرض ۱۹۲ و ارتفاع ۱۹۲، حجم ۴۷۱۰۷ بایت                                                                              |
| هویت تصویر                         | همان نشان موجود سنتی بهجتی؛ بایت‌های فایل زنده با فایل پروژه برابر بودند                                                           |
| سازگاری مرورگر                     | یک `shortcut icon` به `/favicon.ico`، پاسخ 200 با `image/x-icon`؛ یک Apple icon به `/apple-icon.png` با اعلان ۱۸۰×۱۸۰              |
| robots.txt                         | HTTP 200؛ گروه عمومی `User-Agent: *` با `Allow: /`، بدون منع `/icon.png` یا `/favicon.ico` و بدون گروه مسدودکنندهٔ Googlebot-Image |
| متای صفحهٔ اصلی                    | `robots: index, follow` و `googlebot: index, follow, max-image-preview:large`                                                      |
| پاسخ به User-Agentهای آزمایشی گوگل | صفحهٔ اصلی، robots، PNG و ICO همگی 200؛ PNG یکسان و بدون `X-Robots-Tag`، احراز هویت یا صفحهٔ چالش                                  |

SHA-256 فایل PNG، هم روی دامنهٔ اصلی و هم در پروژه:

```text
af56c8ecd453d5418ff881f4e91133d5fb097cbb962205647052cbd47a4fe5e5
```

درخواست با نام User-Agent گوگل جایگزین خزیدن از آی‌پی واقعی Googlebot نیست. سیاست وابسته به IP/کشور، اتفاقات گذشته، لاگ خزیدن واقعی و تصمیم داخلی گوگل با این تست اثبات یا رد نمی‌شوند.

## بررسی پروژه و Production محلی

فروشگاه **Next.js 16.3.8 با App Router** است. فایل‌های مرتبطِ موجود:

- `apps/storefront/src/app/icon.png`: لوگوی PNG مربع ۱۹۲×۱۹۲؛ مسیر فایل‌محور Next.js، سرو در `/icon.png`.
- `apps/storefront/src/app/apple-icon.png`: آیکون Apple با اندازهٔ ۱۸۰×۱۸۰.
- `apps/storefront/public/favicon.ico`: فایل سازگاری قدیمی در `/favicon.ico`.
- `apps/storefront/src/app/layout.tsx`: metadata مربوط به آیکون‌ها؛ HTML نهاییِ بررسی‌شده تگ تکراری یا متناقض نداشت.

فایل واقعی `apps/storefront/.next/server/app/icon.png.body` در خروجی Production محلی وجود داشت و بایت‌به‌بایت با PNG منبع و فایل دریافت‌شده از دامنهٔ اصلی برابر بود. این بررسیِ فایل محلی از بررسی HTTPS عمومی بالا جداست؛ دسترسی به فایل‌سیستم Production وجود نداشت.

قالب Nginx پروژه، مسیرهای عمومی از جمله favicon را به storefront می‌فرستد و Basic Auth ندارد. پاسخ زنده، سرور `nginx/1.24.0 (Ubuntu)` را نشان داد و در این نمونه درخواست‌ها خطای 403/404، نیاز به ورود یا هدر منع ایندکس برای PNG مشاهده نشد. دسترسی SSH، کانفیگ فعال Nginx، پنل CDN/WAF و لاگ سرور در اختیار نبود؛ نبودِ محدودیت برای همهٔ آی‌پی‌ها یا نبودِ CDN ادعا نمی‌شود. تغییر Nginx/CDN بدون شاهد خرابی پیشنهاد نشده است.

## بررسی بعد از Deploy

برای favicon فعلی نیاز به دیپلوی اصلاحی نیست؛ همین فایل و تگ‌ها روی دامنه قابل دریافت‌اند. تغییر این نوبت فقط آزمون و گزارش است. اگر بعداً نسخهٔ تازه‌ای مستقر می‌کنید، همان روال Git پروژه را اجرا کنید؛ migration، seed، تغییر DNS/Nginx یا تغییر آدرس favicon لازم نیست.

در مرورگر **View Page Source** صفحهٔ اصلی را باز کنید و وجود دقیقاً یک تگ زیر را بررسی کنید:

```html
<link rel="icon" href="/icon.png" type="image/png" sizes="192x192" />
```

ترتیب attributeها یا پارامتر نسخهٔ خودکار Next.js ممکن است متفاوت باشد؛ لینک واقعیِ درج‌شده در HTML باید قابل دریافت بماند. در حال حاضر لینک مشاهده‌شده `/icon.png` بدون query است.

فرمان‌های زیر را روی کامپیوتر خودتان یا سرور اجرا کنید:

```bash
curl -I https://sonatibehjati.ir/icon.png
curl -I -A 'Googlebot-Image/1.0' https://sonatibehjati.ir/icon.png
curl -fsS https://sonatibehjati.ir/robots.txt
```

دو درخواست اول باید 200 و `Content-Type: image/png` بدهند؛ فایل باید تصویر باشد، نه HTML یا چالش. این دستورها از HEAD استفاده می‌کنند؛ در این بررسی، GET و بایت‌های فایل هم جداگانه کنترل شدند. برای آزمون خودکار خروجی Production محلی، بعد از بیلد و با API محلی در دسترس، `npm run verify:seo` را اجرا کنید. آزمون تقویت‌شده وجود فقط یک اعلان از هر نوع و تطابق فایل دریافتی با تصویر اصلی را کنترل می‌کند؛ نتیجهٔ آن به‌عنوان نتیجهٔ سرور اصلی گزارش نمی‌شود.

## Google Search Console

1. در property همین دامنه، **URL Inspection** را برای `https://sonatibehjati.ir/` اجرا کنید.
2. **Test Live URL** را بزنید و HTML/منابع صفحه را بررسی کنید. صفحه باید در دسترس خزنده باشد و لینک `/icon.png` در HTML دیده شود. اگر خطای دسترسی گزارش شد، همان خروجی و لاگ سرور مبنای بررسی بعدی است.
3. پس از موفقیت، برای **صفحهٔ اصلی** روی **Request Indexing** بزنید. درخواست ایندکس برای فایل PNG لازم نیست. بررسی favicon به تغییر sitemap یا درخواست برای صفحات نامرتبط نیاز ندارد.
4. نشانی favicon را ثابت نگه دارید. طبق راهنمای گوگل، بازخزش و پردازش ممکن است چند روز تا چند هفته طول بکشد و حتی رعایت همهٔ شرایط، نمایش favicon را تضمین نمی‌کند. تأیید گوگل یا اقدام داخل Search Console از این محیط انجام نشده است.

منابع: [راهنمای رسمی favicon گوگل](https://developers.google.com/search/docs/appearance/favicon-in-search)، [آیکون‌های فایل‌محور Next.js](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/app-icons).
