# نسخهٔ تست واقعی درگاه، بدون پیامک

این نسخه برای تست درگاه سامان از حساب **مدیر اصلی** است. شمارهٔ ترمینال واقعی در تنظیمات خصوصی سرور قرار می‌گیرد. ثبت‌نام، ورود و خرید مشتریان در API بسته می‌مانند؛ هیچ پیامک واقعی یا کد ورود ثابت عمومی استفاده نمی‌شود. API در production اجرا می‌شود.

تست از `https://admin.sonatibehjati.ir/admin/payment-test` شروع می‌شود. مبلغ ثابت **۱۰ هزار تومان** است و از کارت واقعاً کسر می‌شود. پس از تأیید مستقیم بانک، برگشت خودکار وجه درخواست می‌شود. تأیید پرداخت و تأیید برگشت، جداگانه نمایش داده می‌شوند؛ زمان نشستن وجه در کارت به بانک صادرکننده بستگی دارد. این تراکنش سفارش یا مشتری نمی‌سازد و در درآمد فروشگاه محاسبه نمی‌شود.

## نصب بسته روی سرور موجود

بسته شامل `gateway-review.bundle`، `install.sh`، `README.md`، `release.json` و `SHA256SUMS` است. bundle فقط کامیت‌های جدید روی پایهٔ مشخص‌شده در `release.json` را دارد؛ فایل env، کلید پیامک، داده‌های دیتابیس و آپلودهای خصوصی در آن نیستند. انتشار در GitHub برای استفاده از بسته لازم نیست.

پوشهٔ بسته را با روش معمول خودتان به پوشهٔ خانگی کاربر `sonatibehjati` روی سرور منتقل کنید. فرض دستورها این است که پوشه در `~/gateway-review` قرار گرفته است. سپس **با کاربر پروژه**:

```bash
sudo -iu sonatibehjati
cd ~/gateway-review
sha256sum -c SHA256SUMS
bash install.sh 15855486
```

نصب‌کننده از مخزن موجود `/var/www/sonatibehjati` و شاخهٔ `dev` استفاده می‌کند. اگر کامیت پایه روی سرور موجود نباشد، ابتدا آن را از `origin/dev` دریافت می‌کند؛ دسترسی Git معمول پروژه باید برقرار باشد. تغییرات فقط با fast-forward وارد می‌شوند و در صورت تغییرات ثبت‌نشده یا تاریخچهٔ متفاوت، نصب متوقف می‌شود. ابزار سپس تنظیم تست را اعمال می‌کند و همان `deploy/update-production.sh` را برای تولید کلاینت‌ها، بررسی‌ها، build، migration و راه‌اندازی مجدد **فقط همین پروژه** اجرا می‌کند. دیتابیس seed یا reset نمی‌شود و حساب مدیر و فایل‌های خصوصی موجود حفظ می‌شوند.

اگر مسیر پروژه متفاوت است، `SONATI_PROJECT_DIR` را هنگام اجرای نصب‌کننده تعیین کنید. نسخهٔ Node و ابزارهای لازم همان پیش‌نیازهای دیپلوی قبلی پروژه‌اند.

## Nginx

برای این نسخه از `payment-review.conf` استفاده کنید. این کانفیگ فروشگاه را قابل بازدید نگه می‌دارد، ورود عمومی را می‌بندد و مسیر بازگشت بانک را بدون رمز پیش‌نمایش به فروشگاه می‌رساند. **کانفیگ `payment-live.conf` مربوط به مرحلهٔ بعد از آماده شدن پیامک است.**

بعد از نصب برنامه، با کاربر SSH دارای sudo:

```bash
sudo cp -a /etc/nginx/sites-available/sonatibehjati.conf /etc/nginx/sites-available/sonatibehjati.conf.before-gateway-test
sudo install -m 644 /var/www/sonatibehjati/deploy/nginx/payment-review.conf /etc/nginx/sites-available/sonatibehjati.conf
sudo nginx -t
# فقط اگر آزمون موفق بود و هشدار دامنهٔ تکراری وجود نداشت:
sudo systemctl reload nginx
```

گواهی HTTPS و پورت‌های ۳۱۰۰/۴۱۰۰ همان تنظیم قبلی پروژه‌اند. پورت API باید داخلی بماند. این تنظیم به سایت‌های دیگر سرور دست نمی‌زند.

## اجرای تست

۱. با حساب مدیر اصلی وارد پنل شوید و «تست درگاه پرداخت» را باز کنید. همکاران به این صفحه و عملیات آن دسترسی ندارند.

۲. «شروع تست واقعی درگاه سامان» را بزنید. در صورت دریافت توکن، به بانک منتقل می‌شوید. اگر بانک توکن ندهد، خطا و کد پاسخ در تاریخچه ثبت می‌شوند؛ کد ۸ همان «آدرس سرور پذیرنده نامعتبر است» است و باید تنظیم مبدأ درخواست از همین سرور نزد سامان بررسی شود.

۳. یک پرداخت را انجام دهید. نتیجه باید ابتدا تأیید بانک و سپس وضعیت برگشت وجه را نشان بدهد. نتیجه حتی پس از بسته شدن نشست مدیر هم با لینک همان تست قابل مشاهده است. برای جزئیات و ادامهٔ کار، به پنل برگردید.

۴. می‌توانید لغو در بانک را نیز امتحان کنید. اگر وضعیت «در انتظار تأیید» یا «در انتظار برگشت» است، از «پیگیری بانک» استفاده کنید؛ بررسی خودکار نیز ادامه دارد. تا روشن شدن وضعیت، تست جدید بسته می‌ماند. موفقیت تنها با پاسخ معتبر بانک ثبت می‌شود.

کلیدهای احراز هویت مستقل و تنظیم API↔فروشگاه باید از نصب قبلی در env خصوصی موجود باشند. برای این مرحله کلید پیامک یا `bodyId` لازم نیست.

## فرمان تنظیم بدون بسته

اگر همین کامیت‌ها با روش Git دیگری وارد مخزن سرور شده‌اند، با کاربر پروژه کافی است:

```bash
cd /var/www/sonatibehjati
npm run payments:review -- --terminal-id=15855486
bash deploy/update-production.sh
```

این فرمان فقط روی سرور اجرا شود. `payments:review` حالت production، `CUSTOMER_AUTH_ENABLED=false`، `ADMIN_PAYMENT_TEST_ENABLED=true` و درگاه واقعی را تنظیم می‌کند؛ پیامک را از مسیر اجرایی خارج می‌کند و اسرار دیگر را حفظ می‌کند. بعد از آماده شدن پیامک، فعال‌سازی خرید عمومی طبق `docs/payments.md` انجام می‌شود؛ `--activate` تست مدیریتی را غیرفعال می‌کند.
