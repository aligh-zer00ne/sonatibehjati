# هیرو و داستان بدون کادر برجسته

این نسخه جایگزین چیدمان `homepage-v5.md` است. کادر طلایی بزرگ، حاشیه، سایه و محوشدگی پشت متن هیرو حذف شده‌اند. متن کوتاه و دکمه مستقیم روی فضای خالی عکس قرار دارند و سایه‌روشن سراسری با رنگ قهوه‌ای و زرشکی خوانایی را حفظ می‌کند. متن در موبایل هم روی تصویر می‌ماند و زیر آن نمی‌رود. تصاویر موبایل محصولات را در بیشتر عرض قاب نشان می‌دهند؛ تصویر دسکتاپ نسبت ۳:۲ دارد و در سمت چپ، کنار متن قرار می‌گیرد. حرکت زوم مداوم عکس حذف شده، اما تغییر اسلاید، انیمیشن متن و کنترل‌های قابل توقف باقی مانده‌اند.

داستان سنتی بهجتی و اردکان نیز یک بنر تصویری بدون کادر داخلی است. تصویر عمودی مستقل موبایل، بادگیر و سفره را در قاب نگه می‌دارد. لینک‌های تکراری داستان و اردکان در منوی دسکتاپ، منوی موبایل و فوتر با «داستان سنتی بهجتی و اردکان» ادغام شده‌اند. نشانی قدیمی `/#ardakan` برای سازگاری با لینک‌های قبلی همچنان به همان بخش می‌رسد.

## علت افت کیفیت و اصلاح آن

اندازه‌گیری نسخهٔ قبلی در مرورگر نشان داد:

- هیروی دسکتاپ روی نمایشگر دوبرابر، به علت برش `object-cover` به عرض حدود ۲۶۱۷ پیکسل نیاز داشت، اما منبع فقط ۱۹۴۲ پیکسل بود. بخش بزرگی از پیکسل‌ها نیز صرف فضای خالی تصویر پانوراما می‌شد.
- عکس افقی داستان در قاب باریک موبایل به عرض حدود ۱۱۶۱ پیکسل نیاز داشت، اما مرورگر نسخهٔ ۶۴۰ پیکسلی دریافت می‌کرد. انتخاب اندازه بر مبنای عرض قاب، بزرگ‌نمایی ناشی از ارتفاع و برش را حساب نمی‌کرد.
- تصاویر پس از تبدیل اولیه به WebP مجدداً با کیفیت ۸۵ در بهینه‌ساز Next.js فشرده می‌شدند. زوم متحرک و کارت محو روی محصول هم بر ظاهر جزئیات اثر می‌گذاشتند.
- هیروی موبایل از نظر تعداد پیکسل منبع کمبود جدی نداشت؛ مشکل اصلی آن قاب‌بندی محصولات و پوشانده‌شدن عکس توسط کادر متن بود.

تصاویر تازه از خروجی اصلی مدل به **WebP بدون افت** تبدیل شدند. پیکسل‌های RGB هر هشت فایل اصلی با PNG خروجی مدل مقایسه شدند و دقیقاً برابر بودند. در مسیر ارائهٔ این تصاویر، بهینه‌سازی و فشرده‌سازی مجدد Next.js انجام نمی‌شود. نسخه‌های کوچک‌تر نیز از همان خروجی اصلی، با حفظ نسبت و فشرده‌سازی بدون افت ساخته شده‌اند. `picture`، `srcset` و `sizes` با محاسبهٔ عرض لازم برای پوشش ارتفاع قاب، نسخهٔ مناسب نمایشگر را انتخاب می‌کنند.

وضوح مؤثر، نسبت پیکسل‌های منبع به اندازهٔ تصویر پس از پوشش قاب است؛ این عدد با کیفیت چاپ برچسب یا کیفیت عکاسی یکسان نیست:

| بخش و نمایشگر                        |   قبل |   بعد |
| ------------------------------------ | ----: | ----: |
| هیرو، دسکتاپ ۱۴۴۰ پیکسل با تراکم ۲×  | ۱٫۴۸× | ۲٫۱۴× |
| داستان، تبلت ۷۶۸ پیکسل با تراکم ۲×   | ۱٫۲۵× | ۲٫۳۹× |
| داستان، موبایل ۳۹۰ پیکسل با تراکم ۳× | ۱٫۶۶× | ۲٫۸۸× |

خروجی واقعی مدل برای دسکتاپ ۱۵۳۶×۱۰۲۴ و برای موبایل ۱۰۲۴×۱۵۳۶ است؛ این تصاویر 4K نیستند و بزرگ‌نمایی مصنوعی نشده‌اند. نسخهٔ اصلی موبایل در اندازهٔ بررسی‌شده حدود ۹۶٪ نیاز نمایشگر سه‌برابر را پوشش می‌دهد. فایل‌های بدون افت حجم بیشتری دارند: نسخه‌های اصلی حدود ۱٫۶ تا ۱٫۹ مگابایت، و نسخه‌های ۵۱۲/۷۶۸ پیکسلی حدود ۰٫۵ تا ۱٫۱ مگابایت‌اند. مرورگر بر اساس نمایشگر انتخاب می‌کند؛ داستان و اسلایدهای غیرفعال نیز تا زمان نیاز تنبل بارگذاری می‌شوند.

## تصاویر و مرجع تولید

ابزار استفاده‌شده، **image_gen داخلی با مهارت imagegen** است. عکس‌های واقعی محصولات و تصویر معماری قبلی ورودی مرجع بودند. سه صحنهٔ اردهٔ روان، روغن کنجد و ارده‌های طعم‌دار، همراه تصویر داستان، هرکدام دو قاب مستقل دارند. این‌ها بازطراحی مولد بر پایهٔ مرجع هستند، نه عکس مستند جدید از محل تولید.

تمام خروجی‌های نهایی در `apps/storefront/public/images/home/` ذخیره شده‌اند:

- `hero-{tahini,oil,flavored}-desktop-v6.webp` و نسخهٔ ۷۶۸ پیکسلی هرکدام.
- `hero-{tahini,oil,flavored}-mobile-v6.webp` و نسخه‌های ۵۱۲ و ۷۶۸ پیکسلی هرکدام.
- `story-desktop-v6.webp` و نسخهٔ ۷۶۸ پیکسلی.
- `story-mobile-v6.webp` و نسخه‌های ۵۱۲ و ۷۶۸ پیکسلی.

متن کامل درخواست تولید، فایل‌های مرجع، مسیر خروجی‌ها، ابعاد واقعی و حجم هر فایل در [homepage-v6-image-prompts.json](homepage-v6-image-prompts.json) ثبت شده‌اند. اندازه‌گیری قبل و بعد در [homepage-v6-quality.json](homepage-v6-quality.json) قرار دارد. فایل‌های نسخه‌های قبلی برای حفظ تاریخچه باقی مانده‌اند.

## اعتبارسنجی و اجرا

بررسی مرورگر عرض‌های ۳۲۰، ۳۷۵، ۳۹۰، ۴۸۰، ۶۰۰، ۶۴۰، ۷۶۸، ۱۰۲۴ و ۱۴۴۰ را پوشش می‌دهد: نبود اسکرول افقی، متن روی تصویر و بیرون از ناحیهٔ محصولات، نبود کادر پشت متن، لینک‌های ادغام‌شده، کنترل اسلایدر، سبد، جستجو، کاهش حرکت و نمایش بدون JavaScript. بررسی نمایشگرهای Retina دریافت بایت‌های همان فایل آماده‌شده و کفایت وضوح مؤثر را نیز کنترل می‌کند.

```sh
npm run lint
npm run typecheck
CATALOG_SOURCE=mock npm run build
npm run verify:home
```

هر چهار دستور با موفقیت اجرا شدند. پس از بازبینی تصویری، محو شدن لبهٔ عکس در دسکتاپ و فاصلهٔ دکمه از محصولات موبایل نیز تنظیم و بیلد و تست مرورگر دوباره بررسی شدند.

برای اجرای محلی با داده‌های نمونه:

```sh
CATALOG_SOURCE=mock npm run dev:storefront
```

تغییرات داده، دیتابیس و تنظیمات سرور در این اصلاحیه انجام نشده است. انتشار روی دامنه نیازمند انتقال همین کامیت‌ها و اجرای روند به‌روزرسانی سرور است.
