# نقشهٔ سفارش‌ها

در «فروش و مشتریان ← نقشه سفارش‌ها»، نمای اولیه یک نقشهٔ سبک از ۳۱ استان است. پررنگ‌تر بودن استان یعنی تعداد سفارش بیشتر؛ این مقدار تراکم جمعیتی یا سفارش بر کیلومترمربع نیست. لمس، کلیک یا Enter روی استان، فهرست همان استان را باز می‌کند. جدول سهم استان‌ها، سفارش‌های بدون مختصات و استان نامشخص را هم می‌شمارد. نام‌های رایج استان با «ی/ک» عربی، فاصله و پیشوند «استان» یکسان می‌شوند؛ نشانی مبهم به استان حدسی نسبت داده نمی‌شود.

آمار در پایگاه داده از **تمام سفارش‌های مطابق فیلتر** محاسبه می‌شود، مستقل از صفحهٔ ۲۵تایی فهرست. با انتخاب استان، آمار سراسری همان فیلتر ثابت می‌ماند و فهرست محدود می‌شود. فیلترهای وضعیت، محل خرید، روش ارسال، مشتری، شهر، شماره، متن و تاریخ حفظ شده‌اند. داده هر ۳۰ ثانیه در صفحهٔ فعال به‌روز می‌شود. دسترسی مستقل `ORDER_MAP` لازم است؛ مشاهدهٔ جزئیات کامل سفارش همچنان مجوز `ORDERS` می‌خواهد.

## فعال‌کردن نشان

نمای استان‌ها به کلید نیاز ندارد. برای نقشهٔ خیابانی، از حساب خودتان در [پلتفرم نشان](https://platform.neshan.org/) یک **کلید نقشهٔ وب** برای دامنهٔ سایت بگیرید. کلید سرویس مسیریابی/وب‌سرویس جای آن را نمی‌گیرد. کلیدی در مخزن این پروژه پیدا نشد؛ مثال‌های عمومی مجوز استفاده از حساب دیگران نیستند.

در فایل خصوصی `apps/admin/.env` روی سرور، **پیش از ساخت پنل** قرار دهید:

```dotenv
VITE_NESHAN_MAP_KEY=کلید_نقشه_وب_خودتان
```

این کلید برای مرورگر است و در خروجی پنل قابل مشاهده خواهد بود؛ محدودیت دامنه و سهمیه را در حساب نشان تنظیم کنید و آن را در Git ثبت نکنید. سپس به روش معمول منتشر کنید:

```bash
git pull --ff-only origin dev && bash deploy/update-production.sh
```

این تغییر نقشه مهاجرت جدیدی ندارد. مهاجرت اطلاعات فروشگاه از تغییر قبلی را همین اسکریپت اعمال می‌کند. Nginx تنظیم تازه‌ای لازم ندارد؛ اگر روی سرور CSP اختصاصی دارید، دسترسی‌های موردنیاز SDK نشان را طبق مستندات سرویس مجاز کنید.

SDK رسمی `@neshan-maps-platform/leaflet` فقط هنگام انتخاب «نقشه نشان» بارگیری می‌شود. لوگو و حق نشر نشان حفظ می‌شوند. نشانگرهای زرشکی تعداد کل استان را در میانگین مختصات ثبت‌شدهٔ آن نشان می‌دهند؛ این نقطه مرکز رسمی استان یا نشانی همهٔ سفارش‌های آن نیست. نشانگر طلایی مقصد ثبت‌شدهٔ سفارش‌های همین صفحه است. نشانی یا نام مشتری برای ژئوکدینگ به سرویس دیگری فرستاده نمی‌شود. نبود کلید، قطعی سرویس و خطای بارگیری پیام روشن دارند و نمای استان‌ها/فهرست را از دسترس خارج نمی‌کنند.

پس از انتشار با کلید واقعی، ورود مدیر، هر دو نمای نقشه، بارگیری کاشی‌های نشان، بزرگ‌نمایی/جابجایی، انتخاب سفارش، فیلتر استان و رفتار موبایل را بررسی کنید. خطای ۴۰۱/۴۰۳ را در Network مرورگر و محدودیت دامنه/نوع کلید را در حساب نشان کنترل کنید. صرف وجود نقشهٔ استان‌ها به معنی فعال‌بودن سرویس نشان نیست.

## منابع و بررسی محلی

- [بستهٔ رسمی Leaflet نشان](https://www.npmjs.com/package/@neshan-maps-platform/leaflet) و [مستندات SDK وب](https://platform.neshan.org/sdk/web-sdk/).
- [نمونهٔ رسمی قدیمی React/Leaflet](https://github.com/NeshanMaps/react-neshan-map-leaflet) برای مقایسهٔ الگوی اتصال؛ خود کامپوننت قدیمی وارد پروژه نشده است.
- فقط مسیرهای هندسی نقشه از [react-iran-heatmap](https://github.com/cyberhuginn/react-iran-heatmap) استفاده شده‌اند. مجوز MIT و انتساب در `apps/admin/public/map/iran-provinces-LICENSE.txt` هستند؛ اسکریپت یا دادهٔ سفارش از آن پروژه وارد نشده است. شناسه‌های نقشه داخلی‌اند.

```bash
npm run verify:order-map
```

بررسی از حساب‌ها و سفارش‌های موقت استفاده و پس از پایان آن‌ها را پاک می‌کند. آمار فراتر از صفحه‌بندی، نام‌های معادل استان، مقصدهای بدون GPS، دسترسی، فیلترها، انتخاب با صفحه‌کلید، SDK واقعی با کاشی‌های آزمایشی محلی و اندازه‌های ۳۲۰ تا ۱۴۴۰ بررسی می‌شوند. هیچ کلید واقعی یا پرداخت/پیامک واقعی مصرف نمی‌شود. این بررسی تأیید اتصال یا سرعت شبکهٔ Production نشان نیست؛ آن مرحله پس از تنظیم کلید حساب خودتان انجام می‌شود.
