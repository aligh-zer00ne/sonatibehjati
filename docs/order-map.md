# نقشهٔ سفارش‌ها

در «فروش و مشتریان ← نقشه سفارش‌ها»، نمای اولیه یک نقشهٔ سبک از ۳۱ استان است. پررنگ‌تر بودن استان یعنی تعداد سفارش بیشتر؛ این مقدار تراکم جمعیتی یا سفارش بر کیلومترمربع نیست. لمس، کلیک یا Enter روی استان، فهرست همان استان را باز می‌کند. جدول سهم استان‌ها، سفارش‌های بدون مختصات و استان نامشخص را هم می‌شمارد. نام‌های رایج استان با «ی/ک» عربی، فاصله و پیشوند «استان» یکسان می‌شوند؛ نشانی مبهم به استان حدسی نسبت داده نمی‌شود.

آمار در پایگاه داده از **تمام سفارش‌های مطابق فیلتر** محاسبه می‌شود، مستقل از صفحهٔ ۲۵تایی فهرست. با انتخاب استان، آمار سراسری همان فیلتر ثابت می‌ماند و فهرست محدود می‌شود. فیلترهای وضعیت، محل خرید، روش ارسال، مشتری، شهر، شماره، متن و تاریخ حفظ شده‌اند. داده هر ۳۰ ثانیه در صفحهٔ فعال به‌روز می‌شود. دسترسی مستقل `ORDER_MAP` لازم است؛ مشاهدهٔ جزئیات کامل سفارش همچنان مجوز `ORDERS` می‌خواهد.

## انتشار

نقشهٔ استان‌ها کاملاً داخل پروژه است و کلید، SDK یا سرویس نقشهٔ بیرونی لازم ندارد. طبق اصلاح کارفرما، اتصال نشان و تنظیم آن حذف شدند. اطلاعات مقصد از خود سفارش خوانده می‌شوند.

```bash
git pull --ff-only origin dev && bash deploy/update-production.sh
```

این اصلاح مهاجرت یا تنظیم محیط/Nginx جدید ندارد. مهاجرت اطلاعات فروشگاه از تغییر قبلی را همین اسکریپت اعمال می‌کند.

## منبع و بررسی محلی

فقط مسیرهای هندسی نقشه از [react-iran-heatmap](https://github.com/cyberhuginn/react-iran-heatmap) استفاده شده‌اند. مجوز MIT و انتساب در `apps/admin/public/map/iran-provinces-LICENSE.txt` هستند؛ اسکریپت یا دادهٔ سفارش از آن پروژه وارد نشده است. شناسه‌های نقشه داخلی‌اند.

```bash
npm run verify:order-map
```

بررسی از حساب‌ها و سفارش‌های موقت استفاده و پس از پایان آن‌ها را پاک می‌کند. آمار فراتر از صفحه‌بندی، نام‌های معادل استان، مقصدهای بدون GPS، دسترسی، فیلترها، انتخاب با صفحه‌کلید، نبود درخواست به سرویس نقشهٔ بیرونی و اندازه‌های ۳۲۰ تا ۱۴۴۰ بررسی می‌شوند. هیچ کلید واقعی یا پرداخت/پیامک واقعی مصرف نمی‌شود.
