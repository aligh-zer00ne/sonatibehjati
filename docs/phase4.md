# فاز ۴ — Commerce

مسیرهای فروشگاه، دسته‌بندی، جزئیات محصول، جستجو، سبد مهمان و علاقه‌مندی‌ها پیاده‌سازی شده‌اند. فازهای ۵ و ۶ (OTP و Checkout) هنوز اجرا نشده‌اند؛ دکمهٔ تکمیل سفارش وضعیت غیرفعال را به‌وضوح نشان می‌دهد.

## صفحه‌ها و تعاملات

- `/shop` و `/category/[slug]`: دسته‌ها، جستجو، فیلتر قیمت، پنج نوع مرتب‌سازی، شبکهٔ محصول و صفحه‌بندی؛ پارامترهای `q`, `category`, `sort`, `min`, `max`, `page`, `size` در URL حفظ می‌شوند. اعداد فارسی پذیرفته می‌شوند؛ ورودی نامعتبر پیام اصلاح و امکان پاک‌کردن دارد.
- `/search`: نتایج جستجوی سمت سرور؛ حروف عربی کاف/یاء و فاصله‌ها یکسان می‌شوند. فرم جستجو بدون JavaScript هم قابل استفاده است.
- `/product/[slug]`: metadata اختصاصی، گالری و بزرگ‌نمایی، عنوان، قیمت، وزن واقعی ثبت‌شده، کنترل تعداد، افزودن، علاقه‌مندی، مشخصات و محصولات مرتبط. تب‌ها با صفحه‌کلید RTL قابل پیمایش‌اند. وزن، تخفیف، امتیاز و عکس اضافی ساختگی تولید نمی‌شود.
- `/cart`: دریافت مجدد محصولات و قیمت‌ها، تغییر تعداد، حذف، جمع مبلغ، بازیابی خطای شبکه، نمایش و حذف محصولات ناموجود. هزینهٔ ارسال و تخفیف به Checkout وابسته‌اند.
- `/favorites`: فهرست ذخیره‌شده، حذف و پاک‌سازی موارد ناموجود.

ناوبری موبایل مسیر فعال را مشخص می‌کند؛ منو، کارت، جستجوی سریع و سبد سریع به صفحه‌های اصلی Commerce وصل هستند. استایل‌ها در className با Tailwind و primitiveهای shadcn نوشته شده‌اند. وکتورها، حرکت‌ها و prefers-reduced-motion حفظ شده‌اند. رندر اولیهٔ سبد تا hydration ذخیرهٔ مرورگر Skeleton نشان می‌دهد؛ کاتالوگ و محصول بدون JavaScript محتوای قابل مشاهده دارند. دیالوگ پس از بسته‌شدن تمرکز را به دکمهٔ بازکننده برمی‌گرداند.

## قرارداد API

`catalog(input: CatalogInput!)` فیلترها را اعتبارسنجی می‌کند و `items`, `total`, `page`, `pageSize`, `totalPages` برمی‌گرداند. شمارش و دریافت صفحه در transaction Prisma انجام می‌شوند؛ ترتیب‌ها شناسهٔ ثابت برای تساوی دارند. فقط محصولات فعال خوانده می‌شوند. `excludeSlug` برای محصولات مرتبط است.

`productsByIds(ids: [ID!]!)` فهرست محدود و بدون تکرار محصولات فعال را برای سبد/علاقه‌مندی می‌خواند. Route داخلی `/api/catalog/selection` درخواست POST را اعتبارسنجی و بدون cache پاسخ می‌دهد؛ شکست API به نمونهٔ mock تبدیل نمی‌شود.

حدود: عبارت جستجو ۱۰۰ حرف، صفحهٔ ۱ تا ۱۰۰۰۰، اندازهٔ صفحهٔ ۱ تا ۲۴، قیمت صحیح تومان از صفر تا سقف Int، حداکثر ۲۰۰ شناسه با طول ۱ تا ۱۰۰، حداکثر ۹۹ عدد از هر محصول. ذخیرهٔ مرورگر پالایش می‌شود و قیمت در آن نگهداری نمی‌شود. محاسبهٔ نمایشی سبد جای محاسبهٔ معتبر سمت سرور هنگام Checkout را نمی‌گیرد.

تایپ‌های GraphQL از schema با Codegen تولید می‌شوند؛ قرارداد فیلتر و محدودیت‌های سبد در `packages/shared` مشترک است. منبع کاتالوگ `mock` یا `api` صریح انتخاب می‌شود.

## بررسی

- `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `npm run format:check`.
- ۲۳ تست واحد: محدودیت‌های ورودی، نرمال‌سازی فارسی، فیلتر ترکیبی، ترتیب و صفحه‌بندی، پالایش ذخیرهٔ سبد و جمع با قیمت جاری، و تست‌های قبلی API.
- `npm run verify:api` روی MySQL 8.4 آزمایشی migrated/seeded: فیلتر ترکیبی، جستجوی فارسی، ترتیب/صفحه‌بندی، حذف محصول مرتبط، دریافت فعال‌ها برای سبد و رد ورودی نامعتبر. داده‌های موقت آزمون پس از اجرا پاک می‌شوند.
- `npm run verify:home`: حفظ رفتار صفحهٔ اصلی، favicon، ناوبری جدید دسته، سبد، حرکت‌ها، reduced motion و SSR بدون JavaScript.
- `npm run verify:commerce`: URL و history، جستجو/فیلتر/صفحه‌بندی، گالری، تمرکز و تب‌های صفحه‌کلید، علاقه‌مندی و سبد پس از reload، مبلغ و تعداد، حذف، خطا و retry، موارد ناموجود، ورودی حجیم، مسیر ناموجود و SSR بدون JavaScript.
- Chrome در عرض‌های ۳۲۰، ۳۹۰، ۷۶۸ و ۱۴۴۰؛ نبود overflow افقی و خطای اجرا. اسکرین‌شات‌های `/tmp/behjati-phase4-*` برای بررسی بصری محلی تولید می‌شوند.

اخطار فعلی Vite دربارهٔ حجم پوستهٔ Ant Design پنل مدیریت پابرجاست؛ تقسیم صفحات مدیریتی در فاز ۸ انجام می‌شود. عکس‌ها و اطلاعات محصول نمونه‌اند و محدودیت وضوح مرجع همچنان وجود دارد.
