# فاز ۷ — حساب کاربری

مسیرهای `/account`، `/account/profile`، `/account/addresses`، `/account/orders` و `/account/orders/[id]` تکمیل شده‌اند. صفحات فارسی، RTL، موبایل‌محور و با همان primitiveهای shadcn و رنگ‌های مرجع ساخته شده‌اند؛ استایل جدید فقط در className است.

## پروفایل و حفاظت نشست

`updateProfile` فقط نام، نام خانوادگی و ایمیل اختیاری را می‌پذیرد. Zod مشترک در مرورگر، BFF و API اعتبارسنجی می‌کند؛ نام‌ها trim و ایمیل lowercase می‌شود؛ ایمیل خالی در دیتابیس null است. شمارهٔ تأییدشدهٔ ورود فقط خواندنی است؛ API فیلد phone یا userId را برای تغییر پروفایل نمی‌پذیرد. ایمیل صرفاً اطلاعات پروفایل است و تأییدشده محسوب نمی‌شود.

Mutation به Origin مجاز، Bearer و نشست فعال نیاز دارد و سقف ۳۰ درخواست در دقیقه برای هر کاربر دارد. پروفایل بر اساس شناسهٔ نشست تغییر می‌کند. تغییر به تب‌های دیگر با BroadcastChannel بدون ارسال توکن اعلام می‌شود. خروج، محافظت مسیرها و refresh از معماری فاز ۵ استفاده می‌کنند: access فقط در حافظه؛ refresh در HttpOnly cookie. هیچ توکنی برای این فاز در storage مرورگر قرار نمی‌گیرد.

سرور وجود کوکی refresh را پیش از نمایش صفحه بررسی می‌کند؛ AccountShell هویت واقعی را در مرورگر با API تأیید می‌کند و سپس محتوای حساب را نمایش می‌دهد. همهٔ صفحات noindex هستند. پاسخ‌های BFF/API cache نمی‌شوند. Skeleton، خطای قابل تلاش دوباره و حالت خالی برای اطلاعات حساب وجود دارد؛ نتایج دیررس query با کاربر یا فیلتر جدید مخلوط نمی‌شوند.

## نشانی‌ها

ایجاد، ویرایش، حذف با تأیید داخل کارت و تعیین پیش‌فرض، از همان GraphQL و فرم/نقشهٔ Checkout استفاده می‌کنند. Leaflet، انتخاب روی نقشه، جابه‌جایی marker، موقعیت فعلی و reverse geocoding مطابق [فاز ۶](phase6.md) حفظ می‌شوند. مدیریت نشانی به سبد غیرخالی نیاز ندارد. فقط یک نشانی پیش‌فرض ایجاد می‌شود؛ حذف پیش‌فرض، نشانی باقی‌مانده را پیش‌فرض می‌کند. نشانی استفاده‌شده در سفارش طبق محدودیت دیتابیس قابل حذف نیست و پیام فارسی نشان داده می‌شود.

## سفارش‌ها

`myOrders` بر اساس userId نشست، جدیدترین سفارش‌ها را با مرتب‌سازی ثابت createdAt و number نمایش می‌دهد. فیلتر وضعیت و صفحه‌بندی در سرور اجرا می‌شوند؛ حداکثر pageSize بیست، پیش‌فرض ده و سقف شمارهٔ صفحه ده هزار است. count و فهرست در transaction خوانده می‌شوند. تمام وضعیت‌های CREATED، PENDING_PAYMENT، PROCESSING، SHIPPED، DELIVERED و CANCELED برچسب فارسی دارند.

`myOrder` فقط سفارش متعلق به همان کاربر را برمی‌گرداند؛ شناسهٔ ناموجود و سفارش دیگری هر دو NOT_FOUND هستند. محصولات از OrderItem و نشانی از addressSnapshot خوانده می‌شوند؛ هیچ عنوان، قیمت، گیرنده یا نشانی از relation جاری برای جایگزینی اطلاعات تاریخی خوانده نمی‌شود. برای سفارش‌های قدیمی با snapshot ناقص، فیلدهای ثبت‌نشده null هستند و رابط «ثبت نشده» نشان می‌دهد. Seed جدید snapshot کامل تولید می‌کند و سفارش‌های موجود را بازنویسی نمی‌کند.

جزئیات شامل تاریخ شمسی با منطقهٔ زمانی تهران، وضعیت، تعداد و وزن محصولات، قیمت واحد، مبلغ هر ردیف، نشانی تاریخی، گیرنده، کد پستی و جمع محصولات/تخفیف/ارسال/مبلغ سفارش است. صفحهٔ تأیید Checkout اکنون به جزئیات همین سفارش لینک دارد. هیچ دکمهٔ پرداخت یا پرداخت موفق ساختگی ایجاد نشده است؛ سفارش PENDING_PAYMENT همچنان در انتظار پرداخت است.

این پیاده‌سازی بررسی مالکیت برای هر درخواست را مطابق [راهنمای Authorization در OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) در API انجام می‌دهد. مدل فعلی Prisma 6 و دیتابیس موجود حفظ شده‌اند؛ migration جدید لازم نیست.
