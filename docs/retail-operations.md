# مدیریت فروش و ارسال

این تغییر با همان روال معمول Git و `bash deploy/update-production.sh` منتشر می‌شود. اسکریپت، migration افزایشی `202610200001_retail_shipping` را اجرا می‌کند؛ تنظیم جدید محیط، seed یا reset لازم نیست. مبالغ سفارش‌ها و پرداخت‌های قبلی تغییر نمی‌کنند.

## تنظیم محصولات

در ویرایش هر محصول، تب «هزینه و وزن ارسال» را باز کنید و این سه مقدار را ثبت کنید:

- وزن واقعی یک واحد محصول همراه بسته‌بندی، به گرم؛ وزن حجم‌دارهایی مثل روغن را وزن‌کشی کنید.
- هزینهٔ پایهٔ ارسال، به تومان، برای یک کیلو اول بسته.
- هزینهٔ هر کیلو اضافه، به تومان. صفر یعنی بابت وزن اضافه هزینه‌ای دریافت نشود.

برای محصول جدید، وزن و هر دو تعرفه باید صریح وارد شوند؛ صفر هم مجاز است. برای محصولات قدیمی تا زمان تنظیم، هزینهٔ ثابت قبلی حفظ می‌شود. وزن‌های دارای واحد گرم یا کیلو قابل تشخیص‌اند؛ وزن محصولات میلی‌لیتری حدس زده نمی‌شود. اگر تعرفهٔ وزنی فعال باشد ولی وزن یکی از محصولات سبد مشخص نباشد، ثبت خرید برای اصلاح محصول متوقف می‌شود.

برای کل بسته فقط یک هزینه گرفته می‌شود: بیشترین هزینهٔ پایهٔ محصولات + بیشترین نرخ هر کیلو اضافه × تعداد کیلوهای شروع‌شده بعد از کیلو اول. وزن همهٔ اقلام با تعدادشان جمع می‌شود. مثلاً وزن ۲۱۰۰ گرم، دو کیلو اضافه دارد. قیمت‌ها برای هر سه شیوهٔ پست، تیپاکس و پیک یکسان محاسبه می‌شوند؛ انتخاب کاربر، روش تحویل را مشخص می‌کند. تعرفهٔ جداگانه برای هر شرکت درخواست نشده است.

روش ارسال، وزن و مبالغ نهایی هنگام ثبت در سفارش ذخیره می‌شوند؛ ویرایش بعدی محصول، سفارش قدیمی را تغییر نمی‌دهد. محاسبه و کنترل مبلغ نهایی سمت سرور است.

## مشتری و سفارش حضوری یا اینستاگرامی

در «مشتریان»، دکمهٔ «افزودن مشتری» نام، موبایل و منبع را ثبت می‌کند. موبایل تکراری مشتری تازه نمی‌سازد؛ مشتری موجود را انتخاب کنید. این کار پیامکی ارسال نمی‌کند و ورود بعدی مشتری همچنان OTP معمول سایت را دارد.

در «سفارش‌ها»، «ثبت سفارش دستی» را بزنید، مشتری، محل خرید و اقلام را انتخاب کنید. مشتری جدید از همین فرم هم قابل افزودن است، مشروط به داشتن دسترسی مشتریان. کاربر دارای فقط دسترسی سفارش‌ها، جستجوی مشتری و ثبت سفارش را دارد ولی امکان ویرایش مشتری، محصول یا گزارش‌ها را ندارد.

برای تحویل حضوری، گزینهٔ مربوط را روشن بگذارید تا ارسال صفر باشد. برای ارسال، آن گزینه را بردارید، روش ارسال و نشانی کامل گیرنده را وارد کنید. نشانی تاریخی این سفارش مستقل از دفترچهٔ نشانی مشتری ذخیره می‌شود.

مبلغ دریافت‌شده و نوع دریافت (نقد، کارت‌خوان، کارت به کارت) را ثبت کنید. مبلغ صفر و دریافت جزئی مجازند. در جزئیات سفارش، تب پرداخت‌ها، «ثبت دریافت مانده» برای دریافت‌های بعدی است. هر دریافت با مبلغ، روش، زمان و مدیر ثبت‌کننده نگهداری می‌شود. مجموع دریافت بیش از مبلغ سفارش رد می‌شود. تسویهٔ کامل سفارش را وارد «در حال آماده‌سازی» می‌کند. تغییر وضعیت جای ثبت دریافت را نمی‌گیرد.

پرداخت‌های دستی، تأیید بانکی سامان محسوب نمی‌شوند و `paidAt` بانکی را تغییر نمی‌دهند. درگاه آنلاین برای این سفارش‌ها باز نمی‌شود. فاکتور و حساب مشتری، دریافتی فروشگاه و مانده را مشخص می‌کنند. قطع ارتباط پس از ثبت و تلاش مجدد با همان شناسه، سفارش یا دریافت تکراری نمی‌سازد؛ تا مشخص شدن نتیجه از همان دکمهٔ تلاش مجدد استفاده کنید.

## فیلتر و داشبورد

فیلترها به دکمه تبدیل شده‌اند. دکمهٔ فعال علامت نقطه دارد؛ روی آن بزنید تا گزینه‌ها باز شوند. سفارش‌ها، نقشه و گزارش‌ها، محل خرید و شیوهٔ ارسال را نیز فیلتر می‌کنند. مشتریان و خروجی اکسل با محل خرید محدود می‌شوند. محصولات، تیکت‌ها، نظرات، کدهای تخفیف و کاربران پنل فیلترهای مناسب خود را دارند.

داشبورد سه مسیر سایت، اینستاگرام و حضوری را جدا نمایش می‌دهد. مشتری دارای سفارش از چند مسیر، در هر مسیر حساب می‌شود؛ برای مشتری بدون سفارش، منبع ثبت به کار می‌رود. بنابراین جمع تعداد سه گروه الزاماً تعداد یکتای مشتریان نیست.

گزارش، پرداخت موفق درگاه و دریافت ثبت‌شدهٔ مدیر را جدا نشان می‌دهد. جمع آن‌ها «کل دریافتی» است و بر اساس تاریخ دریافت محاسبه می‌شود؛ ارزش سفارش بر اساس تاریخ ثبت سفارش است. ارزش سفارش لغوشده در ارزش فروش نیست؛ وجهی که قبلاً دریافت شده تا زمانی که واقعاً برگشت نخورد، همچنان دریافت تاریخی است.

## نوار اطلاع‌رسانی و ظاهر پنل

«تنظیمات مدیریت ← نوار اطلاع‌رسانی سایت» برای ویرایش و روشن/خاموش کردن نوار قرمز بالای سایت است. هیروسکشن و درباره ما از پنل حذف شده‌اند؛ محتوا و تصاویر فعلی سایت حفظ شده‌اند. منوهای مرتبط گروه‌بندی شده‌اند و فونت کمی وزین‌تر است. عبارت «طراحی توسط nexoraict.ir» در فوتر سایت و پنل، QR، لیبل و فاکتور دیده می‌شود.

## بررسی محلی

`npm run verify:retail-shipping` و `npm run verify:retail-operations` با دیتابیس محلی مهاجرت‌داده‌شده، API ساخته‌شده و دادهٔ موقت اجرا می‌شوند. `npm run verify:retail-ui` بیلد تازهٔ API و پنل را لازم دارد و سرویس‌های موقت 4003/3005 را اجرا می‌کند. تست تسویه‌حساب با `npm run verify:shipping-checkout-ui` از پیش‌نمایش فروشگاه روی 3000 و درخواست‌های شبیه‌سازی‌شده استفاده می‌کند. هیچ‌کدام پیامک یا پرداخت بانکی واقعی ارسال نمی‌کنند.
