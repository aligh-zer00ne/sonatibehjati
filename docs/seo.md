# SEO و GEO سنتی بهجتی

صفحات عمومی فروشگاه، دسته‌بندی‌ها، محصولات، معرفی مجموعه و پرسش‌های متداول برای جست‌وجو آماده شده‌اند. منظور از GEO، دسترسی و فهم بهتر محتوای معتبر سایت برای موتورهای پاسخ‌گوی هوش مصنوعی است؛ ثبت یا رتبهٔ تضمینی در گوگل یا این سامانه‌ها وجود ندارد.

## رفتار پیاده‌سازی

- دامنهٔ مرجع تمام canonicalها، تصاویر اشتراک‌گذاری، شناسه‌های برند و sitemap برابر `https://sonatibehjati.ir` است؛ آدرس localhost وارد هویت عمومی سایت نمی‌شود.
- هر محصول عنوان، توضیح، تصویر اشتراک‌گذاری و `Product/Offer` خود را از کاتالوگ واقعی می‌گیرد. قیمت کاتالوگ تومان است و در JSON-LD با تبدیل ×۱۰ و کد ISO یعنی `IRR` درج می‌شود. فقط تخفیف معتبر در زمان رندر اعمال می‌شود. موجودی انبار، امتیاز، نظر، GTIN، شرایط مرجوعی یا هزینهٔ ارسالِ تأییدنشده ساخته نشده‌اند.
- `OnlineStore`، `WebSite`، `BreadcrumbList`، `CollectionPage`، `AboutPage` و `FAQPage` در HTML سمت سرور درج می‌شوند. متن FAQ از همان منبعی می‌آید که کاربر می‌بیند. JSON-LD در برابر بستن تگ اسکریپت با متن واردشده در پنل escape می‌شود.
- معرفی `/about` از متن دربارهٔ ما در پنل استفاده می‌کند؛ شمارهٔ تماس، اینستاگرام و لینک نشان همان اطلاعات موجود در صفحهٔ QR هستند. نشانی فقط تا سطح شهر/استان درج شده؛ مختصات، نشانی خیابانی و ساعات کاری حدس زده نشده‌اند.
- `/sitemap.xml` پویاست و تمام صفحات کاتالوگ را می‌خواند؛ به سقف ۱۰۰ محصول کوئری صفحهٔ اصلی محدود نیست. فقط محصولات فعال، دسته‌ها و صفحات عمومی ثابت در آن هستند. تاریخ تغییر محصول از `updatedAt` می‌آید؛ تاریخ تغییر ساختگی برای صفحات ثابت ثبت نمی‌شود.
- صفحه‌بندی عادی canonical مستقل دارد. جست‌وجو، مرتب‌سازی و فیلترها noindex هستند. پارامترهای رهگیری canonical را تغییر نمی‌دهند. صفحات بعد از آخرین صفحهٔ کاتالوگ، پیدا نشد برمی‌گردانند.
- حساب، تیکت، ورود، سبد، تسویه و پرداخت با meta و/یا `X-Robots-Tag` از ایندکس خارج‌اند. صفحات HTML دارای noindex در robots مسدود نیستند تا خزنده بتواند دستور را بخواند. این تنظیم جایگزین احراز هویت نیست.
- `/QR`، `/qr` و `/qr.html` با هدر noindex از رقابت با صفحهٔ اصلی خارج می‌شوند. فایل، فونت و ظاهر QR تغییر نکرده است.
- در تولید با `CATALOG_SOURCE=api` خزیدن عمومی باز می‌شود. توسعه و کاتالوگ mock بسته می‌مانند؛ sitemap آن‌ها خالی و متای صفحات عمومی noindex است. برای پیش‌نمایش تولید با اطلاعات واقعی، `SEO_INDEXING_ENABLED=false` را در محیط storefront قرار دهید و بازسازی/راه‌اندازی کنید. در تولید واقعی این متغیر حذف یا `true` باشد.
- قانون عمومی robots شامل خزنده‌های جست‌وجوی هوش مصنوعی مانند `OAI-SearchBot` هم می‌شود. گروه اختصاصی که محدودیت‌ها را دور بزند تعریف نشده است. `/llms.txt` فقط فهرست اختیاری صفحات رسمی است و به‌عنوان شرط ایندکس یا عامل رتبه معرفی نمی‌شود.

## استقرار

در حساب کاربر پروژه روی سرور، همان روال قبلی را اجرا کنید:

```bash
cd /var/www/sonatibehjati
git pull --ff-only origin dev && bash deploy/update-production.sh
```

این تغییر migration، تغییر Nginx، سرویس پولی یا فعال‌سازی پیامک لازم ندارد. تنظیمات پرداخت و ورود آزمایشی دست‌نخورده‌اند. پس از استقرار، `https://sonatibehjati.ir/robots.txt` باید `Allow: /` و آدرس sitemap را نشان دهد؛ sitemap نیز باید URL محصولات فعال را داشته باشد. اگر CDN/WAF یا تنظیم سفارشی Nginx دارید، پاسخ صفحات عمومی و فایل‌های robots/sitemap برای خزنده‌ها باید بدون رمز یا چالش باشد.

## کارهای مربوط به حساب مالک سایت

۱. دامنه را در [Google Search Console](https://search.google.com/search-console) و [Bing Webmaster Tools](https://www.bing.com/webmasters/) تأیید کنید. روش Domain/DNS نیازی به تغییر کد ندارد. دسترسی مالک این حساب‌ها در پروژه موجود نیست و ثبت خارجی انجام نشده است.

۲. اگر روش HTML meta انتخاب شد، فقط مقدار token داده‌شده را در متغیر server-side `GOOGLE_SITE_VERIFICATION` یا `BING_SITE_VERIFICATION` محیط storefront قرار دهید و اسکریپت استقرار را اجرا کنید؛ کد آمادهٔ درج این متاهاست. هیچ token فرضی در خروجی ساخته نمی‌شود.

۳. `https://sonatibehjati.ir/sitemap.xml` را در هر دو کنسول ثبت کنید. صفحهٔ اصلی و چند محصول را با URL Inspection و [Rich Results Test](https://search.google.com/test/rich-results) بررسی کنید. نمایش Rich Result، مخصوصاً FAQ، تضمین نمی‌شود.

۴. طی هفته‌های بعد وضعیت ایندکس، خطاهای خزیدن، عبارت‌های جست‌وجو و Core Web Vitals را با دادهٔ واقعی بررسی کنید. متون کوتاه/موقت محصولات را از پنل با مشخصات واقعی همان محصول تکمیل کنید؛ ادعاهای درمانی، امتیاز و سابقهٔ ساختگی اضافه نکنید. برای توسعهٔ سئوی محلی، نشانی دقیق و ساعات کاریِ تأییدشده را در محتوا و پروفایل‌های رسمی یکسان نگه دارید.

## بررسی محلی

```bash
npm run lint
npm run typecheck
npm test
npm run build -w @behjati/storefront
npm run verify:seo
```

`verify:seo` روی بیلد تولید، سرور موقت با پورت آزاد می‌سازد و بدون خرید، پیامک، تغییر داده یا ثبت خارجی، HTML اولیه، متادیتا، schemaها، sitemap و noindex را بررسی می‌کند. برای حالت تولید کاتالوگ API باید در دسترس باشد. آدرس پیش‌فرض GraphQL همان `http://localhost:4000/graphql` است. `API_URL` را می‌توان صریحاً تغییر داد.
