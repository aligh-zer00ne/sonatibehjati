# مدیریت متمرکز ارسال

از «مدیریت ← مدیریت ارسال» تعرفهٔ **کل بستهٔ سفارش وبسایت** را تعیین کنید. هزینهٔ جداگانه از صفحهٔ محصول حذف شده؛ در محصول فقط وزن واقعی هر واحد همراه بسته‌بندی وارد می‌شود. هزینه‌های قدیمی محصول برای حفظ داده‌ها در دیتابیس باقی می‌مانند و پس از راه‌اندازی سیاست متمرکز در محاسبه استفاده نمی‌شوند.

برای پست، تیپاکس و پیک می‌توانید فعال بودن، هزینهٔ یک کیلوگرم اول، نرخ هر کیلو اضافه و مشمول بودن در ارسال رایگان را جدا تنظیم کنید. مبلغ‌های پنل **ریال** هستند؛ واحد قیمت فروشگاه و ذخیره‌سازی قدیمی تغییر نکرده است. این نرخ‌های توافقی فروشگاه‌اند، نه استعلام لحظه‌ای شرکت حمل؛ برای نرخ واقعیِ وابسته به مقصد/ابعاد باید بعداً سرویس رسمی شرکت حمل متصل شود.

فرمول:

`هزینهٔ پایه + max(۰، ceil(وزن کل بر حسب گرم / ۱۰۰۰) − ۱) × نرخ هر کیلو اضافه`

برای مثال، با پایهٔ ۸۰۰٬۰۰۰ ریال، نرخ اضافهٔ ۱۵۰٬۰۰۰ ریال و وزن کل ۲۱۰۰ گرم، هزینهٔ یک بسته ۱٬۱۰۰٬۰۰۰ ریال است؛ حتی اگر چند محصول داشته باشد. پیش‌نمایش کنار تنظیمات با وزن و مبلغ دلخواه همین محاسبه را نشان می‌دهد. محصولی با وزن نامشخص و تعرفهٔ وزنی قابل محاسبه نیست؛ وزن آن را در ویرایش محصول اصلاح کنید. برای مایعات، وزن واقعی همراه ظرف را وارد کنید؛ حجم به‌جای وزن حدس زده نمی‌شود.

## ارسال رایگان

کلید «ارسال رایگان» را روشن و حداقل خرید را وارد کنید. معیار، جمع **محصولات پس از تخفیف‌ها و کد تخفیف** و بدون هزینهٔ ارسال است. رسیدن دقیق به حداقل هم کافی است. فقط روش‌هایی که «مشمول شرط ارسال رایگان» دارند رایگان می‌شوند. خاموش‌بودن کلید یعنی هیچ وعدهٔ رایگانِ مبتنی بر حداقل خرید فعال نیست.

در تسویهٔ خرید، روش‌های غیرفعال نمایش داده نمی‌شوند. خلاصه، مبلغ باقی‌مانده تا رایگان‌شدن و نوار پیشرفت را نشان می‌دهد. مبلغ نهایی و احراز شرایط فقط در API محاسبه می‌شوند. تغییر مبلغ یا وضعیت روش بعد از پیش‌نمایش باعث الزام به دریافت خلاصهٔ تازه می‌شود؛ یک سفارش ثبت‌شده با تغییر تعرفه دوباره قیمت‌گذاری نمی‌شود. تکرار همان درخواست سفارش هم همان فاکتور قبلی را برمی‌گرداند.

روش و تعرفهٔ همان زمان، مبلغ واجد شرایط و علت رایگان‌شدن در سفارش ذخیره می‌شوند. شیوهٔ ثبت دستی هزینهٔ ارسال اینستاگرام و تحویل حضوری تغییر نکرده است. حداقل یک روش باید فعال باشد. تغییر هم‌زمان دو مدیر با کنترل نسخه محافظت می‌شود. همکار فقط با مجوز مستقل «مدیریت ارسال» می‌تواند تنظیمات را ویرایش کند؛ دسترسی محصول به‌تنهایی این مجوز را نمی‌دهد.

## به‌روزرسانی سرور

```bash
cd /var/www/sonatibehjati
git pull --ff-only origin dev && bash deploy/update-production.sh
```

مایگریشن افزایشی `202610230003_store_shipping` جدول تنظیمات و ستون اختیاری سابقهٔ تعرفه در سفارش را اضافه می‌کند. اسکریپت آن را خودکار اجرا می‌کند؛ seed/reset یا تغییر Nginx و env لازم نیست. در اولین خواندن، تنظیمات یک‌بار با بیشترین تعرفهٔ قبلیِ محصولات فعال و مقدار پیش‌فرض فعلی سرور برای محصول بدون تعرفه ایجاد می‌شود. هر سه روش ابتدا فعال‌اند و شرط ارسال رایگان خاموش است. بعد از انتشار نرخ‌های مرکزی را بازبینی، مبلغ دلخواه برای رایگان‌شدن را تعیین و ذخیره کنید. نمونه‌مبلغ‌های این راهنما پیشنهاد نرخ واقعی حمل نیستند.

## منطق انتخاب‌شده و منابع

[راهنمای رسمی Shopify](https://help.shopify.com/en/manual/fulfillment/setup/shipping-rates/setting-up-shipping-rates) نرخ یک‌بار برای سفارش، وزن مجموع کالاها، تعرفهٔ جدا برای روش‌های ارسال و حداقل خرید رایگان را پشتیبانی می‌کند. [راهنمای رسمی WooCommerce](https://woocommerce.com/document/free-shipping/) نیز شرط حداقل خرید پس از کد تخفیف را توضیح می‌دهد. برای این فروشگاه، ترکیب نرخ وزنی کل بسته با حداقل مبلغ پس از تخفیف انتخاب شد. از تصویر ارسالی باسلام فقط به‌عنوان نمونهٔ بصری فرم پایه/اضافه‌وزن استفاده شده؛ تنظیمات خصوصی یا نرخ زندهٔ باسلام در دسترس نبوده است.

`npm run verify:retail-shipping` محاسبات و مجوزهای API را با دادهٔ موقت بررسی می‌کند؛ `npm run verify:store-shipping-ui` ذخیرهٔ پنل، پیش‌نمایش، روش‌های فعال، پیشرفت رایگان و ثبت سفارش را در مرورگر واقعی می‌آزماید. بیلد تازهٔ API/پنل/فروشگاه و دیتابیس محلی لازم است. تنظیمات اولیه پس از تست برگردانده می‌شوند؛ بانک و پیامک واقعی فراخوانی نمی‌شوند.
